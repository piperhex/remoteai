# Codex GUI 对话工具与引用

普通消息、排队消息和运行中补充不再自动附带其他对话的运行概览，也不会因此读取其他对话。
需要了解当前任务时，助手可以调用内置工具查询；用户要求新建或续聊时，可以直接操作 GUI 对话。

| 工具 | 用途 |
| --- | --- |
| `gui_create_conversation` | 新建对话并发送首条消息，返回对话及轮次 ID |
| `gui_send_message` | 向指定对话续发；正在运行时补充当前轮次 |
| `gui_list_running_conversations` | 查询运行中的对话、项目、名称及总数，包含调用方自身 |
| `gui_read_conversation` | 查询指定对话状态和最近的用户、助手文字 |

例如：“新开一个对话，发送测试”“给刚才的对话补充：请用中文回答”“现在有哪些对话正在运行？”
这些操作不会切换当前选中的对话；新对话和运行状态会同步到侧栏及已连接的远端界面。
新对话默认使用 GUI 保存的新聊天模型及工作区写入权限；省略项目目录时使用独立的无项目对话。
续发保留目标对话自己的模型和权限，不中断它的工作。跨对话发送须来自用户的要求，查询内容仅供参考。

每次新建或续发均需提供新的 `requestId`。网络超时或结果不确定时，使用相同标识和参数重试只返回发送记录，
不会重复发送；相同标识搭配不同内容会被拒绝。`sent` / `steered` 表示消息已接收，不代表回复已完成。
`unknown` 表示结果未确认，应先读取对话，不能换一个标识自动重发。发送记录在应用重启后保留。
如果目标恰好结束运行，补充失败会明确返回状态变化，不会自动转成下一轮消息。

工具由 GUI 启动的 Codex 引擎加载，更新应用并重启后可用；不改写用户的 MCP 配置，也不影响其他 Codex Home。
内置服务只监听本机回环地址，使用每次启动生成的认证信息，并拒绝来自网页的跨域请求。

运行查询每页最多 50 个对话，使用 `nextCursor` 继续；返回查询时间，状态随后可能变化。
读取对话最多返回最近 20 条文字，总计 32,000 个字符，单条最多 4,000 个字符，并标记截断。
不包含工具输出、附件内容或历史自动附加的对话快照。

输入 `@` 可搜索未归档的其他对话，运行中的对话优先显示。方向键选择，Enter 或 Tab 添加引用，
Escape 关闭菜单。引用显示为可移除的标签，切换对话保留草稿，排队、编辑重发和失败恢复保留引用。
搜索独立于侧栏筛选，远端 GUI 使用当前连接电脑的对话。

每条消息最多引用 8 个对话，发送时重新读取所选对话，不恢复或中断它们的任务。
每个引用最多携带最近 12 条用户或助手消息，合计最多 48,000 个字符，单条最多 8,000 个字符；
不包含工具输出、附件内容或其他对话引用展开后的内容，截断会告知模型。
引用内容仅作为参考，当前用户消息决定任务。读取失败会阻止发送并保留草稿。

临时无法读取名称的运行中对话仍保留 ID。
所有读取均异步执行，候选菜单每 5 秒刷新一次，未完成的刷新不会重叠，关闭菜单时停止刷新。
历史消息只显示用户文字和引用标签，自动附加的快照不会进入复制或消息编辑文本。
正文与快照合并存储时同样隐藏快照，已加载的旧记录也会在显示时过滤。
中断后继续、失败后重试自动发送的继续指令保持隐藏，不影响上一条用户消息的编辑。

验证入口：桌面 Vitest、Playwright `conversation-mentions.pw.ts` 与 `conversation-context-display.pw.ts`、
Rust `conversation_context` 和 `conversation_tools` 测试。
`node scripts/codex-gui-conversation-context-smoke.mjs <codex.exe 路径>` 使用本地 Responses 夹具验证
已安装 CLI 的上下文传递与历史边界，不消耗模型额度。
`node scripts/codex-gui-conversation-tools-smoke.mjs <codex.exe 路径>` 验证四个工具进入模型请求、
实际 MCP 调用，以及重载配置、恢复对话后的可用性。启动参数中的全部 `-c` 必须位于 `app-server` 后，
否则 CLI 会在存在子命令配置时忽略子命令前的工具配置。
