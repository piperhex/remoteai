# 聊天提醒、任务状态与连接体检

原生手机端和 Web 聊天页共用任务状态及连接体检逻辑。点击聊天标题下的 P2P／Relay 连接状态，
可查看账号验证、电脑在线、直连／中转、电脑聊天四个环节及下一步操作。
连接中或断线时，也可点击同一位置的状态打开连接抽屉。
中转连接可正常发送任务；设备列表的旧在线状态不会覆盖当前可用的聊天连接。

## 关键提醒

- 审批、补充问题、成功完成和失败事件由桌面 Rust 接收，不依赖主 WebView 发起推送。
- 启用云账号时，先在应用数据目录的 `chat-push-outbox.db` 中提交 SQLite 事务，再发布对应聊天事件。
  WAL 和 `synchronous=FULL` 用于保存待投递记录。记录仅包含路由标识与事件类型，不包含聊天正文或凭据。
- 后台线程在程序启动时恢复投递，不需要等待下一次聊天事件。发送失败采用 5 秒起、最多 5 分钟的退避，
  不设置最大尝试次数，不因断网、限流、认证失败或服务端尚未启用通知而删除记录。
- 只有 `POST /chat-push/events` 的 **204** 回执允许删除本地记录；该接口在 Go 服务端持久化事务成功后回复。
  超时、回执丢失及非 204 响应都会保留事件。重新投递依赖服务端的事件去重。
- 记录绑定原服务器、云账号和设备；切换账号或服务器后保留原记录，回到原账号后继续发送。
  审批 ID 加入 AI 进程实例标识，避免重启后复用请求编号；实时通知和云推送共享同一事件 ID。
- 本地存储失败会在聊天页提示检查电脑空间；这种情况下无法承诺已落盘，需在聊天记录中核对进度。

服务端仍需配置并启用现有推送服务，原生客户端需允许系统通知。204 表示服务器已接收，
不表示手机系统已经展示通知。现有 Expo 投递、收据检查与保留期限继续生效。
Web 同步任务状态和体检界面，本次不新增浏览器系统推送。

## 任务状态

聊天标题下仅显示异常提醒：连接中断后的任务状态待更新、发送结果待核实、任务失败、
待发送消息出错或提醒保存失败。正常发送、接收、运行、完成和待审批不在这里显示，也不占位。
审批仍在聊天中的审批卡片处理；正常进度和结果在聊天内容中查看。原生端与 Web 使用相同规则。

任务状态仍按以下依据区分：

| 状态 | 依据 |
| --- | --- |
| 正在发送 | 消息正在传输 |
| 已发送 | 传输完成，尚未收到电脑的操作回执 |
| 电脑已收到 | 电脑确认操作成功，或消息已进入电脑的持久化待发送列表 |
| AI 已开始处理 | AI 发出运行事件，或同步到正在运行的任务 |
| 等待你的确认 | 有当前待处理的审批／问题 |
| 结果待确认 | AI 报告本次任务完成，用户仍需查看回复和改动 |
| 发送结果待核实 | 操作未获成功回执；不自动重发，避免重复执行 |
| 任务状态待更新 | 当前无可用连接，不能把上次缓存的运行状态当成实时进度 |

新消息不会继承上一任务的完成状态。任务发送回执描述当前客户端的发送操作，
运行、失败和完成依据电脑的事件与历史；聊天重连会同步当前任务、队列和有效审批。
「结果待确认」不表示测试已通过或代码已验收。进度条与回执也不能替代实际代码检查。

## 验证入口

- Rust：`cargo test --manifest-path apps/desktop/src-tauri/Cargo.toml --test codex_switch_lib_tests`
- Go：`go -C apps/admin test ./internal/chatpush`
- 原生：`npm --prefix apps/native run test`
- Web：`npm --prefix apps/web run test:chat:e2e -- --grep "shows only task issues"`

回归覆盖超过旧队列容量的落盘、数据库重开、退避和去重、账号隔离、HTTP 回执校验、
传输与操作回执乱序、未知执行结果，以及窄屏／宽屏下直连、中转、审批和断线恢复。
