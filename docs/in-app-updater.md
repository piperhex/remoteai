# 应用内更新发布配置

桌面应用使用 Tauri Updater，在后台检查并下载 GitHub Release 的 `latest.json`
中与当前平台匹配的已签名更新包。设置中的“自动安装更新”默认开启，已下载的
更新会在下次启动时自动安装。关闭后仍会检查和下载更新，但重启时不会自动
安装；用户仍可手动安装更新。此设置保存在本机，重新开启后恢复启动时自动安装。

用户手动安装已下载的更新前，应用会再次检查最新版本。如果有更新版本，则改为
下载该版本，完成后等待用户再次点击安装；没有更新版本时才安装已下载的版本。
检查最多等待 30 秒（包含重试）；检查失败或超时时保留已下载的更新，恢复弹窗操作，
用户可以重试或稍后安装。超时后才返回的检查结果不会替换已下载的版本。

Android 应用在“设置 → 关于 Remote AI”中通过 GitHub Release API 检查
最新正式版本。发现更新后，系统 DownloadManager 会在后台下载安装包，下载
完成后应用会调用 Android 系统安装器。首次安装应用内更新时，用户可能需要在
系统设置中允许 Remote AI“安装未知应用”。

## 电脑之间自动分享更新包

版本检查始终从 GitHub 的 `latest.json` 获取版本、下载地址和签名。匹配更新包时，
登录中的电脑可以跨账号自动分享已经下载并通过官方签名校验的文件。
下载顺序为本机已验证缓存、持有同一更新包的电脑、GitHub 原始下载地址。
对端无法连接、离线、传输中断、文件异常或签名校验失败时，自动回退 GitHub，无需再次点击下载。
缓存不可读或写入失败不会阻止官方下载与安装。

- 电脑通过现有 `/device-switch` 连接报告最多三个更新包标识；服务器仅匹配文件和分配临时直连会话。
  不发送其他账号的设备名称、账户资料、聊天记录或更新版本信息，也不通过服务器中转更新包。
- 每份文件用版本、目标平台、GitHub 下载地址和官方签名共同生成标识。接收后使用应用内置公钥校验完整文件，
  安装时再次核对该文件与 GitHub 检查返回的更新资源相匹配。对端不能提供安装路径或改变待安装版本。
- 下载端最多同时连接三台电脑，每台发送不同范围的分块，合并完整文件后再校验。优先选择同账号电脑，
  不足时使用其他账号的电脑。任一来源失败、范围错误、缺块或校验失败都会结束共享下载并回退 GitHub。
  旧客户端仍可单源下载；多源请求仅匹配支持分块的电脑。
- 每台电脑最多同时上传两路，每路上限 1 MiB/s。共享单包上限 512 MiB，最多缓存两个电脑包和一个 Android APK，
  最长分享 14 天；重启或完成升级后仍可恢复分享。缓存保存在应用缓存目录的 `update-peers` 下。
- 匹配最多等待 6 秒，直连最多等待 12 秒，传输连续 8 秒无数据或持续过慢时回退 GitHub。
  完整传输最多持续 20 分钟；回退时重新计算下载进度。GitHub 下载继续由 Tauri 校验签名。
- 未登录、旧版服务器或未配置直连协调节点时使用 GitHub 下载。手机只接收 APK，不作为上传种子。

先部署支持此功能的 admin-go，再安装新版电脑客户端。复用现有 `CHAT_NATIVE_PEERS`、`CHAT_NATIVE_STUN`
与直连协调节点，不需要新增数据库表或外部文件服务。当前匹配状态保存在单个 admin-go 实例内；
多实例部署时，只有连接到同一实例的电脑能够互相匹配。客户端断开连接后立即停止对应分享会话。

验证需覆盖跨账号匹配、更新包签名错误、对端中断、无种子、旧后端回退、缓存重启恢复，以及升级后的继续分享。
本地测试使用单独的测试签名密钥和本地下载源，不使用正式签名私钥，也不执行安装器。

参考：[Tauri 更新器签名与安装接口](https://v2.tauri.app/plugin/updater/)。

## 手机空闲下载与电脑共享

Android 在应用保持前台、连续一分钟没有触摸操作且连接非计费 Wi-Fi 时，自动查询 GitHub 并预下载更新。
不会自动安装；下载完成后保留安装确认。手动下载允许移动网络，忽略的版本不自动下载；自动检查成功后
间隔六小时再次检查，失败至少间隔十五分钟重试。应用被系统暂停或关闭时不承诺启动新任务，已经交给
DownloadManager 的官方下载可以继续由系统执行。

- 手机从 GitHub Release API 获取 APK 地址、大小和 `digest`；共享前必须有 GitHub 的 SHA-256。
  多台电脑分块写入应用自己的下载目录，完整文件检查大小、SHA-256、包名、版本与当前安装应用的签名。
  校验失败的文件不能安装。无可信摘要时直接从 GitHub 下载，仍核对应用签名。
- 手机登录会话只可申请接收更新包，不能发布种子；过期登录凭据不能申请共享。自己与他人的电脑均可匹配，
  服务端不向手机公开其他账号的身份信息。离线、旧后端、超时、断流、错误分块和坏包均自动回退原始 GitHub URL。
- 自动下载的所有来源均受 Wi-Fi 限制。直连期间失去 Wi-Fi 会中止共享，回退的 DownloadManager 任务也仅允许
  非计费 Wi-Fi，不会改用移动流量。手动下载不加此限制。
- 登录中的电脑在更新下载/上传空闲时，从固定 GitHub 仓库预取最新 Android APK 并核对摘要；每六小时检查一次。
  安卓包与电脑更新包使用各自的校验规则，电脑安装器仍必须通过原有 Minisign 签名校验。
- Web 同步空闲准备逻辑，在浏览器明确报告 Wi-Fi 且未开启节省流量时，预加载本站新版本的同源脚本与样式，
  保持窄屏、宽屏一致，并保留手动刷新确认。无法确认网络类型时不自动预加载；浏览器不下载或安装 APK。
  iOS 保持原更新入口，不使用 Android 的 APK 下载与系统安装能力。

摘要来源：[GitHub Release Assets API](https://docs.github.com/en/rest/releases/assets)。
系统网络限制：[Android DownloadManager.Request](https://developer.android.com/reference/android/app/DownloadManager.Request)。

## 一次性配置

1. 将本机私钥文件 `apps/desktop/src-tauri/.updater/codex-switch.key` 的完整内容保存为仓库 Actions Secret：`TAURI_SIGNING_PRIVATE_KEY`。
2. 私钥绝不能提交、公开或替换。该文件已被 `.gitignore` 忽略；丢失它会导致已发布版本无法验证后续更新。
3. 提交并推送本次改动后，按现有流程创建 `vX.Y.Z` tag。Release 工作流会使用这个 Secret 签名安装包并上传 `latest.json` 与签名文件。

## 发布要求

应用显示名称为 Remote AI。应用标识、数据目录、深链协议和更新源继续沿用原有值，
保证已有账号、设置和更新客户端可继续使用。MSI 的 `upgradeCode` 固定为改名前的值；
NSIS 默认安装会复用旧安装目录，安装成功后移除旧名称的卸载登记并更新对应快捷方式。
Android 发布资产仍沿用 `CodexSwitch-android-` 前缀，供旧版电脑客户端识别下载入口；
iOS 预构建项目和 scheme 随显示名称使用 `RemoteAI`。

- `apps/desktop/package.json`、`apps/desktop/src-tauri/tauri.conf.json` 和 `apps/desktop/src-tauri/Cargo.toml` 的版本必须一致，并且新 tag 的版本号更高。
- `apps/native/app.json` 的 `expo.version` 和 Android `versionCode` 由发布脚本同步；不要手工复用旧的 `versionCode`，否则 Android 会拒绝覆盖安装。
- Android Release 必须包含名称带 `android` 且以 `.apk` 结尾的资产。当前工作流使用 `CodexSwitch-android-vX.Y.Z.apk`。
- Windows 发布使用 NSIS 更新包，避免 MSI 安装需要管理员权限的常见问题。
- GitHub Release 必须是已发布状态。草稿 Release 不会被 `releases/latest` 端点返回。

## 验证

手机和 Web 的“设置 → 电脑端版本”通过 `/device-switch` WebSocket 读取同账号电脑的版本，
支持检查更新及确认后远程安装。需要先部署支持 `app-update` 的 admin-go，并在电脑上安装
支持此能力的版本；旧电脑仍显示上次连接时的版本，远程更新按钮禁用，无需数据库升级。
指令仅转发到当前账号的目标电脑，下载和签名校验复用电脑端更新器。安装前会核对确认的
版本；如果版本变化，需要重新检查并确认。页面关闭不取消已发送的安装，断线和超时不会
自动重发安装指令；重新连接后读取实际版本，仅匹配目标版本才显示更新完成。

验证远程更新时，分别在手机和 Web 窄屏、宽屏打开此入口，检查离线电脑、旧版电脑、
无更新、下载失败、重复点击及安装后重连。安装会重启电脑端，应在测试安装环境中验证。

发布新版本后，在安装了旧版本的 Windows 或 macOS 应用中启动 Remote AI。出现更新提示后，选择“安装更新”；应用应下载、校验签名、安装并重启到新版本。

在安装了旧版本的 Android 设备上进入“设置 → 关于 Remote AI”，点击
“检查更新”。确认后台下载后，可离开该页面并在通知栏查看进度；下载完成后
应出现安装确认，系统安装器显示的目标版本应与 Release tag 一致。
