# Coze 知识库与数据表迁移说明

本次把上游文档来源、图片识别、扫描 PDF、字段定义和自然语言查询能力接入 Remote AI 的 Rust 运行包。
保留原有本地向量模型、全文检索、引用、分段编辑和知识库隔离。无 Go 服务、容器、外部数据库或单独 OCR 服务。

## 功能与入口

| 能力 | 当前行为 |
| --- | --- |
| 普通文档 | TXT、Markdown、可提取文字的 PDF、DOCX、CSV、TSV、JSON、XLSX；本地解析、切分、索引 |
| 网页资料 | 在知识库的「网页」页签导入公开 HTTPS 页面；提取可见文字，保存来源地址和更新时间 |
| 网页更新 | 点击「更新网页内容」；保留文档 ID，重新抓取、切分和索引，成功后原子替换旧内容 |
| 图片知识 | PNG、JPEG、WebP；所选视觉模型识别文字并描述图片，结果进入同一知识检索体系 |
| 原图 | 原始图片保存在本地知识库，点击「查看原图」才返回预览数据 |
| 扫描 PDF | 勾选「识别扫描 PDF 中的文字」，逐页在 Rust 中渲染，再由视觉模型识别；分段保留页码 |
| 进度与取消 | 文件读取、网页读取、识别页数、整理分段数；支持取消正在等待的模型请求和网页请求 |
| 数据表字段 | 文本、整数、数字、布尔、带时区日期时间、JSON；必填校验，乐观修订，验证已有数据后保存 |
| 表格导入 | CSV、TSV、XLSX；首行作为字段名，Excel 取首个工作表；整批事务写入或全部回滚 |
| 记录浏览 | 分页读取和编辑；导入超过 1,000 条记录后仍可逐页查看 |
| SQL 查询 | 查询所选数据表，支持关联、筛选、分组、聚合和有限窗口函数；不会修改记录 |
| 自然语言查询 | 经现有本地代理生成 SQL，校验后供用户查看，再点击运行；仅向模型提供表结构和问题 |

工作流可复用同一知识库导入、删除、SQL 和自然语言查询服务。相关节点由工作流模块维护。

## 模型与数据

图片和扫描 PDF 必须选择支持图片输入的模型。调用复用 Remote AI 已选择的账户及本地代理，
不需要额外填写 OCR 服务地址或密钥。文档内容会按该账户的现有模型路由发送给模型服务；
“本地代理”不表示视觉识别必定离线。普通文本解析、向量化和检索仍在本机进行。

识别结果由模型产生，可能漏字、误读或描述不准确。原文件保留在本地，用户可查看识别后的分段并修正；
此实现没有把模型输出当作经过人工校对的文字。图片检索使用识别出的文字及描述，不是图像向量相似度检索。

来源元数据存入 `document_sources`；原文件继续保存在 `documents.source`。
网页重新导入按内容和来源去重；刷新通过原有文件摘要校验并在同一事务中替换原文、分段和索引。
解析、网络、模型或向量化失败不会删除原有可用版本。取消在分段生成、事务写入和提交前均有检查。

## 范围与限制

- 文档最大 32 MB，图片最大 16 MB，扫描 PDF 最多 50 页；每页渲染长边不超过 1,800 像素。
- 扫描 PDF 使用纯 Rust 的 [Hayro 0.7.1](https://docs.rs/hayro/0.7.1/hayro/)；
  复杂透明效果、特殊字体或其他未完整支持的 PDF 特性可能影响识别。没有密码输入流程。
- 每页渲染是同步 CPU 工作；取消可中断页间流程和页内模型等待，但不会强制中断一个已经开始的页面渲染。
  页数、尺寸和对象数有上限，这不是对任意恶意 PDF 提供的进程级内存沙箱。
- 网页最多跟随 5 次跳转，内容最大 2 MB；每一跳都重新校验 HTTPS 目标、解析并固定公开 IP。
  禁止私网、环回、链路本地和特殊地址，禁用系统 HTTP 代理，不传递 Remote AI 的本地凭据。
- 网页导入只提取当前页面，不执行 JavaScript、不自动登录、不递归抓取站点；目前接受 UTF-8 页面。
- 表格每次最多导入 10,000 行和 100 列。CSV 保留 `00123` 等前导零标识，明确数字和布尔值保留类型。
  XLSX 数值和布尔值保留类型；Excel 日期单元格按读取器的文本表示导入，需要带时区字段时应先整理数据。
- 单次 SQL 最多选择 8 张表，每张快照最多 10,000 行，总记录 JSON 最大 2 MB；超过限制直接提示，避免静默漏算。
  结果最多 1,000 行并标记截断，总结果最大 2 MB。表按选择顺序命名为 `t1`、`t2` 等。
- SQL 使用独立的内存数据库，只复制用户选择的数据表；运行库的资源、凭据、会话等表从未附加到该连接。
  语句必须只读，授权器禁止写入、附件数据库、内部表和非白名单函数，并有执行步数与时间限制。
- 自然语言查询不会保证语义正确；模型生成的查询始终经过上述限制，但用户仍需检查字段和筛选条件。
- 结构化数据表与文档知识库分别维护。向知识库导入 Excel 会生成文本分段；需要类型、聚合、关联时应导入数据表。

## PDF 外部访问审查

核对了下载依赖中的 `hayro 0.7.1`、`hayro-interpret 0.7.0`、`hayro-syntax 0.7.2` 源码。
生产渲染路径接收内存字节，没有网络客户端或打开任意文件的实现。
`InterpreterSettings::default()` 在默认特性下读取编译进二进制的标准字体与 CMap；
本项目没有注册系统字体扫描、文件读取或网络下载回调。
因此 PDF 内的链接和字体名不会作为网络请求或本地文件路径执行。

字体、颜色资源和 CMap 的许可文本保存在 `apps/coze/licenses/hayro-*.txt`，随独立包分发。

## 验证

本次知识库测试覆盖：HTML 可见文本和实体、SSRF 地址限制、来源刷新原子性和冲突、原图保留、
实际扫描页图像渲染（检查生成 PNG 的尺寸及红色像素）、本地视觉请求格式、分段索引中取消、
等待中的视觉请求取消后没有文档落库。已有知识导入、检索、持久化和分段编辑用例继续保留。

数据表测试覆盖：关联聚合、内部表/元数据/扩展/写入拒绝、递归 SQL 预算、字段类型和陈旧修订、
CSV 引号及多行字段、标识保留、批量导入回滚、分页总量和不重复记录。

```powershell
cargo test --manifest-path apps/coze/Cargo.toml --lib knowledge
cargo test --manifest-path apps/coze/Cargo.toml --lib tables
npm --prefix apps/coze run build
```

上述模型测试使用本地协议测试服务，PDF 测试为可复现的合成扫描页；
这些测试验证调用、渲染、取消和存储行为，不代替真实模型对复杂扫描件的识别质量评估。
