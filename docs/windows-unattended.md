# Windows 无人值守远程桌面

继续使用现有手机和 Web 的“远程桌面”入口。Windows x64 安装包包含可选系统服务，
不需要 RustDesk 客户端。该服务只提供远程桌面；电脑尚未登录时，聊天页面会提示先使用桌面登录。
登录后正常应用上线，聊天、账号和项目功能恢复。

## 启用与停用

1. 按 `apps/admin-go/DEPLOYMENT.md` 执行两份 20260928 升级脚本，更新 Go 和网关，
   设置 `DESKTOP_SERVICE_ENABLED=true`。协调地址必须使用 HTTPS/WSS。
2. 使用 `npm run build:app` 构建 Windows x64 包。脚本先生成视频 helper 和独立服务宿主，
   下载并校验固定版本 Node，再把资源摘要编译进程序。仅构建前端不会生成可安装系统服务。
   发布 CI 同样准备这些资源，并解包最终 MSI，核对 Node、宿主和视频组件与程序内置摘要一致。
3. 在电脑上登录需要绑定的云端账号，进入设置中的远程桌面权限，选择“启用无人值守”。
   Windows 会要求管理员确认；应用本身仍可按普通用户运行。
4. 手机/Web 登录同一账号，连接这台电脑，打开远程桌面。主应用离线时服务接管连接；
   主应用在线时保持原入口，将媒体和输入交给系统服务。切换登录桌面时媒体会重新连接。
5. 停用时在电脑设置点击“停用并卸载”。离线卸载仍停止并删除本机服务；如果云端撤销失败，
   界面提示在手机/Web 的设备菜单选择“撤销无人值守授权”。该操作也可用于电脑不在手边的情况。

已安装的无人值守暂时停止或无法访问时，权限修改会提示先重新启用或卸载无人值守，
避免只修改普通应用的副本、服务重启后仍使用旧权限。本地控制入口故障会触发服务重启恢复。

服务绑定启用时的云端账号与 Windows 用户。退出应用或退出云端账号不自动停用服务；
换账号前应停用，换账号后重新启用。更新应用后通过“更新或重新启用”更新受保护的服务副本。
单独撤销云端授权不删除电脑上的服务文件，恢复访问需要在本机重新启用。
卸载主应用前应先在设置中停用无人值守。主应用与服务副本独立，单独卸载主应用不会移除服务；
如果已卸载主应用，可以先从手机/Web 撤销授权，再重新安装主应用并停用服务。

## 权限与存储

- SCM 名称 `CodexSwitchRemoteDesktop`，自动启动，使用 LocalSystem。
- 程序位于 Windows 的 Program Files 已知目录下 `Codex Switch Remote Desktop`。
  配置位于 ProgramData 的 `CodexSwitchRemoteDesktop/configuration.bin`，使用机器 DPAPI 加密，
  目录限制 SYSTEM 与管理员访问。配置含设备专用凭据与主机身份私钥，不应分享。
- 服务只复制校验通过的打包资源。Node 与独立输入/媒体进程不创建用户界面；
  后者被限制在作业对象内，服务退出时结束子进程。
- 工作进程管道只允许 SYSTEM，服务核验子进程 PID；本地控制管道仅允许 SYSTEM、管理员及
  启用服务的 Windows 用户，并由客户端核验服务 PID。RPC 仅允许桌面操作与权限设置。
- 设备凭据不使用长期账号 JWT，服务器只保存 SHA-256 摘要；设备与账号必须仍然有效。
  手机认证截止时间传到原生媒体层；心跳不能延长该截止时间，单次本地授权最多一小时。
- 普通应用拥有连接优先级，服务不会反复抢占正常聊天。手机/Web 的聊天协议仍加密；
  独立服务宿主的聊天信令目前经过协调转发，桌面媒体继续使用 WebRTC 直连或 TURN。

## 验证范围与上线验收

自动验证覆盖真实 Node 宿主的 TLS 连接、v1/v2 加密协议、受限请求、只读权限、授权期限传递、
凭据绑定/轮换/撤销、普通宿主优先级，以及普通用户会话的 GPU/GDI 采集与连续解码。
测试使用隔离凭据和本地 TLS 协调器，不连接生产账号。

```powershell
node scripts/test-desktop-service.mjs
go -C apps/admin-go test -tags integration ./internal/devices -run TestServiceCredentialLifecycle -count=1
```

第二项只连接仓库隔离测试环境的 localhost:15432，测试数据通过事务回滚。
第一项使用 Windows Git 附带的 OpenSSL 生成临时证书；不会修改机器信任存储。

2026-10-01 已在 Windows 11 Hyper-V 虚拟机实际安装 LocalSystem 服务，使用隔离凭据调用真实服务管道，
经 WebRTC 接收到物理控制台的 1024×768 锁屏画面，确认持续解码及直连状态。测试期间普通用户的 RDP
会话保持登录，证明捕获来自物理控制台而非 RDP 桌面。先用固定局域网候选验证捕获，再使用默认浏览器
及公网 STUN 重新建立直连并持续解码锁屏画面；这不代表复杂公网 NAT 成功率验收。

实测修复了连续请求重建命名管道导致服务退出的问题；监听器在交付连接前创建后继实例，始终持有同名管道及 ACL。
回归覆盖前序客户端保留句柄和不完整请求提前断开。视频初始化改在异步运行时执行，避免独立工作进程入口线程栈溢出。
普通应用的远程桌面入口还须验证 Tauri 分发阶段：异步任务在交给运行时前，会先在 Windows 主线程构造。
视频管道读取缓冲区改为编码器持有的可复用堆内存，避免它随重试及超时任务层层内嵌，导致打开桌面时栈溢出。
本地可使用 release 模式运行 IPC 栈回归测试，在 1 MiB 栈上执行真实生成的 IPC 分发代码，并限制打开与信令任务的大小；
仅直接调用媒体层或仅运行 debug 模式的采集测试，不能覆盖此问题。
发布流程不再单独执行此项 release 模式检查。
2026-10-01 使用 Android 14 真机连接 Windows 11 Hyper-V 虚拟机中的正式编译修复版，
连续三次打开均获得 1708×960 桌面画面，显示 UDP 直连；远程“显示桌面”及恢复窗口生效，
首次连接持续超过四分钟，主进程保持运行，测试期间未新增 Windows 或 Android 崩溃记录。
该验证覆盖普通已登录 GUI 会话，不替代以下无人值守场景的验证。
尚需补充重启后登录、连接中锁屏/解锁、UAC 画面、屏幕热插拔、长时间运行及跨账号权限的完整设备矩阵。

2026-10-05 在 Windows 11 Hyper-V 虚拟机复现并修复无人值守的鼠标、键盘输入被拒绝：
绑定输入桌面的句柄必须包含 `DESKTOP_JOURNALPLAYBACK`。原有权限允许 `SetThreadDesktop` 成功，
但 `SendInput` 仍返回 0 和错误码 5；补上这一项权限后，普通桌面和 SYSTEM 所在的物理控制台
`Winlogon` 桌面均接受输入，无需申请桌面完全控制权限。视频采集句柄不执行输入，保持原权限。
新增回归直接使用生产代码绑定桌面，分别发送零位移鼠标事件和 F24 松键，并验证线程桌面恢复；
原代码失败、修复后通过，编译后的 Rust 回归程序也在虚拟机的 SYSTEM 控制台会话通过。
该验证不输入或提交登录凭据，不替代完整登录、锁屏/解锁和 UAC 交互验收。

```powershell
cargo test --manifest-path apps/desktop/src-tauri/Cargo.toml --test codex_switch_lib_tests `
  bound_desktop_accepts_mouse_and_keyboard_input_and_restores_thread -- --ignored --nocapture
```

此测试默认跳过，需显式在可交互的 Windows 桌面运行；验证登录界面时须由 SYSTEM 在活动物理
控制台会话运行，普通管理员或 Hyper-V 增强会话不等同于该环境。更新桌面应用后，仍需在设置中
选择“更新或重新启用”，将修复同步到已安装的无人值守服务副本。

目前只支持活动物理控制台会话，不提供多用户 RDP 会话选择。尚未实现安全注意序列
Ctrl+Alt+Delete；强制要求该序列的登录策略不能据此承诺可远程登录。BitLocker 开机前解锁、
UEFI、断电/关机状态不在 Windows 服务能力内。不会开启自动登录或降低 UAC。
