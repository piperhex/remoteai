# 聊天转发流量统计

Admin 仪表盘展示累计总流量、所选时段流量、每日流量和所选日期的 24 小时分布。
近 7、30、90 天跟随仪表盘的时段选择；流量日期统一按北京时间（UTC+8），无流量的日期和小时补零。
累计总流量不受时段选择影响。历史数据从本功能启用后开始积累，无法补算此前的转发量。

## 统计口径

- 统计 `/device-chat` 中成功写入目标 WebSocket 的 `relay` 消息，覆盖旧版转发和可恢复连接。
- 两个方向合计，每次转发只计一次，不将同一份消息的服务器收、发重复相加。
- 字节数采用转发消息 JSON 的 UTF-8 长度，包括加密内容和消息封装，不包含 WebSocket、TLS、TCP 头。
- 直连流量、信令、认证、拒绝转发、目标离线及写入失败不计入；通过转发链路发送的加密保活也会计入。
- 全站汇总保存小时、统计进程标识和字节总数；个人统计另保存用户 ID、月份、小时和字节总数。
- 不保存聊天内容。个人统计从升级后开始积累，旧全站统计无法分摊到个人。

## 持久化与接口

先执行 `apps/admin/sql/20260922-chat-relay-traffic.sql`，再更新后台和 admin UI。
数据库按 UTC 小时保存各进程的累计字节数，读取时合并进程并按北京时间分组。
写入每 5 秒合并一次；读取仪表盘和正常关闭服务时也会写入待保存的统计。
同一进程的重复写入取较大累计值，避免数据库响应丢失后重试造成重复计数。
全站汇总写入失败时保留待写数据并重试；个人额度校验遇到数据库不可用时会暂停转发，见下文。
异常终止可能丢失尚未写入的统计；数据库故障期间若进程退出，未保存数据同样无法恢复。

受 `admin.dashboard.read` 权限保护的 `GET /admin/api/dashboard/overview?days=7|30|90`
新增 `chatTraffic` 字段：

```ts
{
  totalBytes: number;
  daily: Array<{
    date: string;          // 北京时间 YYYY-MM-DD
    bytes: number;         // 当日合计
    hourlyBytes: number[]; // 24 个元素，依次对应 00:00–23:00
  }>;
}
```

## 每位用户的聊天流量与额度

先执行 `apps/admin/sql/20260923-chat-user-traffic.sql`，再更新 admin-go 和管理页面。
全新空数据库会自动初始化新增的三张表。升级脚本可重复执行，不修改已有聊天或全站统计。

独立的「聊天流量」页面支持选择月份、搜索邮箱、分页查看所有用户（包括零流量用户），
查看个人累计流量、所选月份流量和本月额度。用户详情提供每日图表、24 小时分布及逐小时表格。
「设置额度」支持 B / MB / GB，按 1024 换算，服务端保存精确字节数。

- 额度默认 `-1`（不限量），`0` 禁止服务器转发；正数为每月字节上限。
- 按北京时间每月 1 日 00:00 切换统计月份，不需要清空历史数据或运行重置任务。
- 同一用户的全部设备、两个方向、旧版和可恢复会话共用额度；重连和重启不会重新获得额度。
- P2P 内容不计入；可恢复会话即使当前使用 P2P，备用转发链路的加密保活仍计入。
- 每条消息在目标 WebSocket 的写入任务中校验额度；数据库用户行锁串行化同一用户的发送与额度修改，
  覆盖有限超时的网络写入。不同用户互不串行，连接路由锁和 PC UI 线程不执行数据库操作。
- 一条完整消息超过剩余额度时拒绝转发，失败写入回滚用量。增大额度后可继续转发，降低额度不抹去本月已用量。
- 个人小时和月份统计随转发同步提交。数据库不可用时暂停转发并保留 P2P 信令；恢复后自动重试。
  网络写入后若数据库提交失败或进程异常退出，已发消息可能无法计入，不能将这些统计当作链路层精确账单。

管理 API：

- `GET /admin/api/chat-traffic/users?month=YYYY-MM&search=邮箱&page=1&pageSize=20`
- `GET /admin/api/chat-traffic/users/:id?month=YYYY-MM`
- `PATCH /admin/api/chat-traffic/users/:id/limit`，请求 `{ "monthlyLimitBytes": -1 }`

读取需要 `admin.chat-traffic.read`，额度修改需要 `admin.chat-traffic.manage`，修改会写审计记录。
内置管理员自动获得新权限；自定义角色需要授予相应权限。普通用户不能读取他人的统计或修改额度。

## PC 连接详情

点击标题栏设备连接状态，弹层列出当前连接、客户端名称、P2P / Relay 状态、发送和接收的转发量，
并显示账号本月已用流量和额度。客户端名称是展示信息，不作为身份或额度归属依据；旧客户端显示通用设备名。
服务器约每 5 秒推送统计，前端通过事件更新，不增加文件、数据库轮询。
本次连接计数在会话重连时保留；服务器重启重建会话时重新开始，个人月用量仍从数据库恢复。

## 验证

`go test ./...` 覆盖月份边界和补零。启动固定本地 PostgreSQL 测试环境后，
设置 `ADMIN_GO_TRAFFIC_DB_TEST=1` 再运行 `go test ./internal/chattraffic`，验证并发额度、写入失败回滚、
不限量和跨月用量。`node apps/admin/scripts/chat-traffic-smoke.mjs` 验证真实 WebSocket、
HTTP 权限、参数校验、用户检索、双向流量、会话恢复、旧版协议及额度调整。
桌面端 `relayQuota.test.ts` 验证加密 P2P 在额度用完后继续工作，`connection-details.pw.ts` 验证实时更新期间的交互。
